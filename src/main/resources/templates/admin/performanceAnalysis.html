N+1 Query & Hibernate Bag

Il Problema N+1: Quando carichiamo una lista di entità (es. Squadre) e per ciascuna di esse accediamo a una collezione lazy (es. Giocatori), Hibernate esegue 1 query iniziale per le squadre e N query per caricare i giocatori di ogni squadra. Questo degrada drasticamente i tempi di risposta all'aumentare di N.

Hibernate MultipleBagFetchException: In JPA non è possibile eseguire il JOIN FETCH simultaneo di più collezioni di tipo List (chiamate "bag"). Per ottimizzare ed evitare l'eccezione, abbiamo implementato una strategia multi-query coordinata che riduce le query a sole 2, caricando l'intero grafo di oggetti in memoria.

Dettaglio dell'Ottimizzazione

Di seguito viene riportato il confronto del codice Java e JPQL utilizzato nelle due rispettive strategie messe a benchmark:

1. Strategia inefficiente (Lazy Loading)
// 1. Carica il Torneo dal DB (1 query) Torneo torneo = torneoRepository.findById(id).orElse(null); // 2. Naviga la relazione ed ottiene la lista squadre (1 query aggiuntiva all'accesso) for(Squadra s : torneo.getSquadre()) { // 3. Per ciascuna squadra, accede ai giocatori (N query aggiuntive) List<Giocatore> giocatori = s.getGiocatori(); giocatori.size(); // Innesca la query Lazy } // Query totali generate: 2 + N (Dove N è il numero di squadre)
2. Strategia ottimizzata (Multi-Query JOIN FETCH)
// Query 1 in TorneoRepository (JOIN FETCH del torneo e delle sue squadre in un'unica operazione) @Query("SELECT DISTINCT t FROM Torneo t LEFT JOIN FETCH t.squadre WHERE t.id = :id") Optional<Torneo> findByIdWithSquadre(@Param("id") Long id); // Query 2 in TorneoRepository (JOIN FETCH di tutte le rose dei giocatori per le squadre in esame) @Query("SELECT DISTINCT s FROM Squadra s LEFT JOIN FETCH s.giocatori WHERE s IN :squadre") List<Squadra> fetchSquadreWithGiocatori(@Param("squadre") List<Squadra> squadre); // Utilizzo nel Service Layer: Torneo t = torneoRepository.findByIdWithSquadre(id).orElse(null); if (t != null && !t.getSquadre().isEmpty()) { torneoRepository.fetchSquadreWithGiocatori(t.getSquadre()); } // Query totali generate: esattamente 2. Previene il problema N+1 ed evita MultipleBagFetchException.
